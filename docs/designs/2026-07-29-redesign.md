# Design: Huaming Hub + Email Desk redesign

**Date:** 2026-07-29  
**Status:** draft — awaiting Eric approval  
**Route:** A · dual identity (buyer catalogue × personal dispatch)  
**Scope:** visual system + information architecture; static sites; no mail API  

**Repos:**  
- Hub: `~/Github/huaming-hub` → https://erict16.github.io/huaming-hub/  
- Desk: `~/Github/email-desk` → https://erict16.github.io/email-desk/  

---

## 1. Goal / non-goals

### Goal

1. **Huaming Hub** — 买家 3 秒内能：找 PDF、认系列、进选型。像工程资料库，不像营销站。  
2. **Email Desk** — Eric 的**邮件工作流核心**：今天下一步、会在哪、单在哪条管线。打开即调度，不是待办清单皮肤。  
3. 两站**故意不同身份**（对外冷静目录 / 对内密调度台），但都克制、可扫、无 AI 模板感。  
4. 内容模型尽量兼容：Desk 仍以 `content/board.md` 为唯一日常源；Hub 仍 EN 默认 + `/zh`。

### Non-goals

- 不接 Spark / 企业邮 API、不实时同步邮箱  
- 不在 Desk 里做报价计算、选型、发信  
- 不恢复 Hub 深色 band / 大图 hero 营销风  
- 不把 Desk 做成 7 列桌面 Kanban 为主视图（窄屏/手机是主使用场景之一）  
- 不强制改 `board.md` 字段名（可**新增可选**字段，旧字段继续解析）  
- 本次不改 `oltc-selector` 本体（仅外链）

## 3. Huaming Hub

### 3.1 Jobs (priority)

1. **找官方 PDF**（型号 / 系列 / 关键词）  
2. **认产品系列**再下钻  
3. **打开选型器**（外链）  
4. 语言切换 EN ↔ 中文  

### 3.2 Information architecture

```
/                 Home — 身份 + 直达资料 + 系列速览
/downloads/       资料库（主工作台）
/products/        系列目录
/zh/*             中文镜像
↗ oltc-selector   外链工具
```

**导航（全局）：** 资料 | 系列 | 选型 ↗ | 语言  

**首页不再讲长故事。** 结构：

```
┌─────────────────────────────────────────┐
│ sticky: logo · 资料 · 系列 · 选型↗ · 文  │
├─────────────────────────────────────────┤
│ kicker: Unofficial reference · Huaming  │
│ H1: OLTC / DETC documents & series      │
│ one-line lead（无宣传腔）                 │
│ [ Browse documents ]  [ Product series ] │
├─────────────────────────────────────────┤
│ 资料库 — 一句 + 链到 /downloads + 数量    │
│ 系列速览 — 6 系列紧凑列表（名+一句+进目录）│
│ 选型 — 一行工具条外链                     │
│ 页脚：非官方声明 + intl-huaming.com       │
└─────────────────────────────────────────┘
```

- 删除或压成一行：原「三步 howto」编号清单（易显 AI 模板；内容可并进 lead 或 downloads 空状态）  
- **Downloads** 是功能中心：粘性搜索、系列/类型筛选、表格等宽型号列  
- **Products** 按 family 分组；型谱用 mono；每组进 downloads 过滤深链（若已有 query 则保留）

| Surface | `--paper-2` | `#ffffff` | 卡片/表 |
| Soft | `--paper-3` | `#e8eef4` | 表头、chip |
| Ink | `--ink` | `#0c1f33` | 近墨蓝黑 |

## 4. Email Desk — 邮件工作流核心

### 4.1 Product thesis

Desk 不是「公开的待办页」，而是 **Eric 海外销售邮件工作流的作战图**：

| 层 | 问题 | 数据从哪来 |
|----|------|------------|
| **今日 Today** | 我现在要回/催/发什么？ | `priority: P0|P1` 的 todo 卡 |
| **管线 Pipeline** | 每张单卡在 OS→…→提货 的哪一格？ | `orders` + `stage:` |
| **旁路 Later** | 可盯可不盯 | `priority: P2` |
| **日程 Dock** | 今天/本周要参加的会 | frontmatter `meetings:` |

原则（硬）：

1. **3 秒：** 紧急数、下一步动作、会、管线拥堵段  
2. **标题 = 邮箱搜索词**（复制友好，UI 提供一键复制）  
3. **Todo = 你要动；Order = 项目在哪** — 同标题可双边出现，UI 互链  
4. **`action` 是卡片主句**（今日区最大；订单区称「卡点」）  
5. **公开站**不展示金额/机密附件内容（写作纪律，UI 不新增金额字段）

### 4.2 Information architecture

```
┌─ sticky header ─────────────────────────────┐
│ logo · Email Desk · 更新时间 · 分享 · 下载MD │
├─ focus strip ───────────────────────────────┤
│ 会：…                                        │
│ [紧急 n] [今日 n] [管线 n] [P2 n]  ← 锚点跳转 │
├─ 今日行动 ──────────────────────────────────┤
│ P0 卡…  P1 卡…   （P2 不在此）               │
├─ 订单管线 ──────────────────────────────────┤
│ 按 stage 分组竖滑（非 7 列 Kanban）           │
│ 每组：阶段名 · hint · count · 进度点         │
│ 卡：标题 · 客户 · 卡点 · 与「今日」互链标记   │
├─ 稍后 ──────────────────────────────────────┤
│ P2 折叠默认开或按数量；视觉更淡              │
├─ 工作流图例（页底或可折叠）──────────────────┤
│ 7 阶段释义 · 字段提示 · Hub / 选型 链        │
└─────────────────────────────────────────────┘
```

**统计跳转：**

| Chip | 跳到 |
|------|------|
| 紧急 | `#today` 内 P0（或仅 P0 子锚） |
| 今日 | `#today`（P0+P1） |
| 管线 | `#pipeline` |
| 稍后 | `#later`（P2） |

**订单阶段**（不变，与现 skill 对齐）：

```
os → tech → qs → po → erp → docs → ship
OS   技术  QS  等PO 投产  单证  提货
```

- 竖向 **stage lanes**（非横 Kanban）  
- 每卡微型进度：7 点，当前点实心 accent  
- `sc` 仍映射 `erp`  

### 4.3 Card models

#### Today card（行动卡）

```
|▌ 标题（可复制）                    date
|  待办 · {action}                  ← 主视觉条
|  tags…
|  发件人：…
|  meta（次级，最多两行，可截断）
|  [若管线有同标题 → 「管线 · {stage}」链]
```

- P0：左侧 3px 红条，**不**显示「P0」字样 chip  
- P1：无红条，其余同构  
- 主条：浅暖底 + 强 action 文案（现「待办 ·」保留语义，视觉可更干净）

#### Pipeline card（状态卡）

```
标题（可复制） · customer
● ● ● ○ ○ ○ ○   stage short
卡点 · {action}
tags · people
meta 一行
[若今日有同标题 → 「今日有待办」链回]
```

#### Later card

- 同 Today 结构但降对比、无红条；section 标题「稍后」

### 4.4 board.md contract（兼容优先）

**保持：**

```yaml
---
title, subtitle, updated, tz, meetings
---
## todo | …
### {searchable title}
- priority: P0|P1|P2|FYI
- date, meta, tags, people, action

## orders | …
### {searchable title}
- stage, customer, date, meta, tags, people, action
```

**解析规则沿用：**

- 展示分区：P0→紧急/今日，P1→今日，P2→稍后，`stage:`→管线  
- `FYI` 不渲染  
- 标题去重仅用于**互链**（字符串规范化：trim + 折叠空白），不合并卡片  

**可选增强（不强制写）：**

| 字段 | 含义 | UI |
|------|------|-----|
| `blocked: true` | 卡在别人 | 管线卡小标记「阻塞」 |
| `ref: {同标题}` | 显式互链 | 若缺则标题匹配 |

首版可只做**标题自动互链**，不加新字段。

### 4.5 Visual system (Desk)

**Subject grounding:** 邮件作战室 · 标签 · 阶段 · 下一步动作  

| Role | Token | Hex |
|------|-------|-----|
| Page | `--bg` | `#f7f6f3` | 暖纸，和 Hub 冷纸区分 |
| Surface | `--surface` | `#ffffff` |
| Ink | `--ink` | `#1a1a1a` |
| Mute | `--mute` | `#5c5c5c` |
| Faint | `--faint` | `#8a8a8a` |
| Line | `--line` | `#e6e4df` |
| Urgent | `--urgent` | `#c43c2c` | P0 条 / 紧急数 |
| Action | `--action-bg` | `#f3ead2` | 待办条 |
| Action ink | `--action-ink` | `#5c4a1f` |
| Pipeline | `--pipe` | `#1f4d7a` | 阶段/卡点 |
| Pipe soft | `--pipe-soft` | `#e8eef4` |
| Follow | `--follow` | `#b86e00` | 今日非 P0 统计 |

- **Type:** 系统 UI 栈优先（`-apple-system, "Segoe UI", …`）+ **tabuler** 数字；阶段 short 可用 mono  
  - Desk **不用** 展示性谷歌字体（加载快、像工具）  
- **宽度：** `max-width: 52rem`（`--measure`）— 单列扫读  
- **Radius:** 6px 卡片；进度点 round  
- **Signature element:** **「待办/卡点」动作条**作为每张卡的视觉脊骨；页顶 focus strip 的紧急数字用 urgent 色。  

**禁止：** 紫渐变、bento 大卡片墙、玻璃拟态、重阴影、知会区回归。

### 4.6 Workflow kit（页底）

可折叠「工作流」：

1. 七阶段一行释义（与 `order-stages.ts` 一致）  
2. 写作提示：标题可搜、tag 人话、todo≠订单  
3. 外链：Huaming Hub · 选型器  

这是 Desk 作为「核心」的**教具层**，不是装饰。

### 4.7 Desk success criteria

- [ ] 首屏见：更新时间、会、紧急数、至少一张 P0 的 action  
- [ ] P0/P1/P2/管线分区与跳转正确  
- [ ] 同标题 todo↔order 互链可见  
- [ ] 标题一键复制  
- [ ] `board.md` 零修改仍可构建；现有样例板渲染正确  
- [ ] 手机单列可完整操作

## 6. Implementation order (after approval)

1. **Sketch（可选但推荐）**  
   - Hub：1–2 个 HTML 首页方向（若 A 已够明确可 skip，直接 frontend-design）  
   - Desk：2 个方向 — *Dense dispatch* vs *Editorial calm* — 仅 Desk 需要比稿时做  
2. **Lock tokens** → 各写/重写 `design.md`  
3. **Desk IA + components**（价值最高，先做）  
4. **Hub IA + components**  
5. **Copy pass** `avoid-ai-writing`  
6. **a11y** focus-visible / reduced-motion / 对比度  
7. Build + Pages 部署；commit/push  

### Suggested PR/commit slices

1. Desk: tokens + shell + focus strip  
2. Desk: Today / Later cards + copy + cross-link  
3. Desk: Pipeline lanes + progress  
4. Hub: tokens + shell + home IA  
5. Hub: downloads/products polish

## 7. Risks / open questions

| Risk | Mitigation |
|------|------------|
| 互链标题不完全一致 | 规范化匹配；不匹配则无链，不报错 |
| Plex 字体增加 Hub 加载 | 子集 woff2；仅 400/600 |
| Desk 暖纸 vs 旧白画布 | 对比足够即可；可在 sketch 微调 |
| 信息架构改完不习惯 | 保留字段语义；只改呈现 |

**Open（实现前可默认）：**

1. Desk 标题复制：默认做。  
2. P2 默认展开：卡 ≤3 展开，>3 折叠。  
3. Hub 字体：IBM Plex；若你讨厌 Plex 再换 Source Sans 3。
